I said I would finish writing about Endian design, and I wasn't lying! I just finished adding a blame feature to the reflector, and I did some cleanup on the base mod repo, so I'm ready to get going! That is, on a later date, because I should really be going to be soon.

Anyways, the overall structure/hierarchy is this:

  • something - a "class" definition or "template" or "interface"
    • something_coms - a component is a struct that is given to each instance of a something; the values of the component can be different per something.
    • something_tags - a tag is applied to each type of something, not each individual instance. A tag holds no data; it only specifies what this type of something is.
    • something_rich_tags - a rich tag is the same as a tag, except it can hold data. The data it holds is constant, cannot change at runtime, and cannot change between instances of something.

I realize now that this sort of goes against jblow's "low friction" ideology. I'm not sure if there's a way to remove the friction without completely changing how this works.

This is just the structure of the mod. I will write about actual gameplay later. Time for bed!
